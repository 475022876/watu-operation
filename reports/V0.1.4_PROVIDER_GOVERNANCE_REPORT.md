## 1. 要求①：真实网页检索与权威站点全文抓取

**供应商注册表**（`lib/mos/adapters/websearch.js`，不写死）：

| 模式 | 密钥 | 说明 |
| --- | --- | --- |
| `searxng` | 不需要 | 自建元搜索，需开 `search.formats: [json]`；**不计费**，适合内网 |
| `brave` / `bing` / `google` / `tavily` | 需要 | 按次计费；Google 额外需要 `cx` |

**全文抓取**（`lib/mos/research-fetch.js`）：只允许文本类 Content-Type；体积/超时上限；
**逐跳** SSRF 复检（DNS 全量解析 + 私网/环回/云元数据拒绝）；正文以
`<<<UNTRUSTED_EXTERNAL_CONTENT …>>>` 边界包裹，防止把网页内容当指令执行。

**关键修正（本版）**：抓取模块的 URL 校验路径原先会经由 `wsConfig()` 连带加载数据库
（`store` 打开数据目录并打印日志），既污染子进程探针输出，也让"纯校验"碰到真实 `data/`。
现改为**只读 `config.json`/env 的研究配置**，语义不变、副作用归零（`research013` J-01/J-03 由假失败转真通过）。

**自检证据**：`sec` 17/17（SSRF/协议/端口/重定向）、`research013` 79/79（含 `J-02` 逐条"生产口径拒绝"）、
`PB` 段检索真实请求命中替身。

## 3. 要求③：真实图像与视频

**图像**（`adapters/image.js`）
- 业务比例 → 供应商尺寸：`1:1 → 1024x1024`、`16:9 → 1536x1024`（`PB-11`：技术参数不下放给员工）。
- 双返回形态：`b64_json`（`PB-10` 真实字节）与 `url`（`PB-12` 二次下载落盘）。
- 未配置 → `NOT_CONFIGURED`，**不生成占位图**。

**视频**（`adapters/video.js`，本版新增）
```
POST /api/mos/video-renders      → start：POST {baseUrl}/v1/videos      （拿到 providerJobId，立即返回）
GET  /api/mos/video-renders/:id  → check：GET  /v1/videos/{id}          （queued/in_progress/completed/failed）
                                 → download：GET /v1/videos/{id}/content （落盘 MP4，上限 120MB）
```
- `PB-13` 提交成功拿到任务 id；`PB-14` 首次 `PENDING` **不谎报完成**；`PB-15` 第二次 `COMPLETED`；
  `PB-16` **真实文件落盘**（非占位）；`PB-17` 未配置 → `NOT_CONFIGURED`，绝不产出占位成片；
  `PC4-12` 未配置时能力声明里**不出现** `AI_RENDER`。

> 为什么不做"一键出片"：长连接会被供应商重复计时并放大失败成本。三步各自记账、可查、可取消。

## 4. 要求④：运行治理六件事

| 要求 | 实现 | 关键断言 |
| --- | --- | --- |
| **密钥安全** | AES-256-GCM 落库 `{v,iv,tag,ct,kf}`；主密钥 `MOS_SECRET_KEY` 优先；掩码 + 指纹；落库前统一脱敏 | `PA-05/06/07/20`（响应无明文、库文件无明文）、`PC4-08`（可逆且不泄露中段）、`PC4-09`（账本全字段脱敏）、`PB-18`（轮换后 `SECRET_KEY_MISMATCH`）、`SET-03…07`（DOM/接口/库文件） |
| **调用权限** | 配置类 `settings.manage`（仅 `MOS_ADMIN`）；调用类 `model.invoke`；越权写审计 | `PA-01`(401)、`PA-11`(P1→403)、`PA-12`(审计)、`SET-09/10/11`（P2 无入口、直链无数据、接口 403） |
| **超时与重试** | 硬超时（AbortSignal）；有界重试上限 3；仅 4 类错误可重试；遵守 `Retry-After`，否则指数退避 400ms→8s | `PB-04`（503 重试后成功 attempts=3）、`PB-05`（慢响应 `PROVIDER_TIMEOUT`）、`PC-16`（429 解析 retryAfter） |
| **费用控制** | 单次预估 + 当月已发生双阈值；`0` = 不设上限；超限**零出站**；记账只认回执 | `PB-06`（超单次上限 → `BUDGET_EXCEEDED` 且 `calls=0`）、`PC4-10`（确认费用与未回执 `unknownCount` 分开统计） |
| **敏感数据外传限制** | 四级分类；正则识别身份证/银行卡/手机/邮箱/受限标记；取"声明与检测更严者"；`CONFIDENTIAL` 需开关、`RESTRICTED` 需审批人 | `PB-07`（身份证号 → `BLOCKED_DATA_CLASS` 零出站）、`PB-08`（分级取更严者）、`PB-09`（豁免后可发）、`PC4-01…04`、`PA-17`（未填确认人 → `ACK_REQUIRED`） |
| **日志与错误处理** | 账本记录每次调用（成功/失败/重试/耗时/tokens/回执金额），滚动 2000 条；P50/P95、错误率、费用汇总；10 个稳定错误码 | `PA-19/20`、`PC4-09/10`、`PA-21`（清密钥后回落 `NOT_CONFIGURED`，不留"假可用"） |

**就绪度不可自封**：`PA-14` 证明有真实成功调用后晋级 `REAL`；`PC4-11` 证明**清除账本即回落** `CONFIGURED_NOT_TESTED`。

## 6. 要让某项真正变成 `REAL`，需要做的三步

1. 侧边栏 → **系统接入** → 选供应商模式（如文本 `openai`）。
2. 填端点（`https://api.openai.com`）、模型名（如 `gpt-4o-mini`）、**粘贴真实密钥** → 保存。
3. 点 **测试连接**（发一次最小真实请求，maxTokens=16）。
   - 成功 → 账本留痕 → 该卡片徽标变 `REAL`；
   - 失败 → 卡片显示错误码与原因，可对照 `docs/PROVIDER_INTEGRATION_GUIDE.md` §7 处置。

> 生产部署请务必注入 `MOS_SECRET_KEY`（`openssl rand -hex 32`），否则主密钥落在 `data/.mos-secret.key`，
> 迁移机器时容易与数据库分离。
