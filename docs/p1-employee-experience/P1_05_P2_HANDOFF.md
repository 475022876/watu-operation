# P1-05 P2交接与停止点

日期：2026-11-02。P1为静态交互设计，本轮结束后停止。P2尚未授权或执行。

## P2的建议范围

按P0的R2路线，独立组件化原型只做我的任务、创作工作区、作品审核三个工作表面；采用合成数据和显式Mock服务边界。先评估并固定必要依赖版本与许可，再安装；不能直接复制LibreChat/Plane整包或运行第三方系统。

原型不修改现有9083应用、不读取业务JSON/生产配置或密钥、不借用真实会话、不自动代理外网。讨论/作品/任务/审核对象分别建模，但不构造第二套生产权威库。Mock能力状态必须可见，生成成功不能冒充真实模型验收。

## 实施顺序

1. 最小组件工程与隔离Mock，建立身份/品牌/任务上下文、显示文案和场景切换。
2. 我的任务：个人视图、任务下一步和选中/返回定位；角色视图条件。
3. 创作：讨论、候选、选定作品、保存/替换/恢复；桌面双栏与窄屏切换。
4. 审核：固定作品、独立专业/发布动作、必填退回意见、修订复审和已批准未发布。
5. 实现32状态的可演示变体，不以随机失败代替可重复脚本；运行U01—U05和权限/错误变体。
6. 中英文、390px、键盘/焦点走查，记录真实用户反馈；确认后再讨论P3接MOS API。

## P2验收门槛

- 三页可连续操作，用户不需要理解版本ID、Skill或Provider。
- 讨论不会自动覆盖当前作品，不通过系统剪贴板搬运正文；只送选定作品。
- 保存失败/冲突/结果未知有不同恢复路径；不送旧稿、不重复决定。
- 无权限/自审/品牌切换/资料撤权变体能展示阻断，不把Mock角色开关视为真实权限校验。
- 专业和发布审批分开，修改后重审，批准交付不等于发布。
- 未接通文件/模型能力如实提示，不伪造读取或生成。
- 桌面与窄屏主要动作可达，关键中英文一致，输入不被翻译。
- 渲染检查、开发者流程、真实员工试用分开记录；没有试用者则仍不得宣称员工可用性通过。

## P3前置事项，不得在P2假装解决

草稿可靠存储、幂等交付与结果查询、多HTTP部分成功、真实同源会话/CSRF、接口能力/错误码适配、资料外发/撤权、实际审核能力和真实模型成本授权。P1/P2的显示状态不是对现有API的更名或新增契约。

## 本轮保护与回滚

P1仅新增docs/p1-employee-experience中的原创设计图、文案、状态说明和本地渲染脚本。运行源码、package/lock、依赖、schema8、PG、Workspace、账号和业务数据不变；无需数据库回滚或重置账号。

所有设计保留为独立Git分支，不合并main、不替换当前员工页面。撤回设计只涉及文档/画板，不能删除历史数据或第三方缓存作为回滚。本轮不自动进入P2。
