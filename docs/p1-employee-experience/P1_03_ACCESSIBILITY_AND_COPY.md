# P1-03 窄屏、键盘与文案规则

日期：2026-11-02。静态图不是可访问性运行测试；以下是P2实现约束。

## 响应式

- 桌面1440×960：任务列表、讨论/作品双栏、作品/审核意见双栏。画板在首屏显示主要动作，不用长说明挤掉作品。
- 390px：导航收进左上菜单；我的任务按卡片显示。创作使用“讨论/当前作品”视图切换，保留两个区域状态，不能重新挂载就清空。
- 审核手机端“作品/审核反馈”切换，底部固定动作打开确认或意见面板，不能一触直接提交。
- 底部固定操作必须为正文预留空间，安全区/键盘弹出时不遮挡正在编辑文字；抽屉/对话框在窄屏可全屏。
- 长任务名、文件名、英文文案与200%缩放不得撑开页面；表格不足宽度时改卡片，不让主要操作只能横向滚动找到。

## 焦点与键盘

1. 列表进入任务后焦点落在任务标题，再按阅读顺序到讨论/作品及主要动作；不依靠颜色传递状态。
2. Tab/Shift+Tab可访问所有动作，输入与附件有明确label；装饰图标不代替名称。
3. 对话框打开后焦点进入标题/首个必要字段，焦点限制在对话框；关闭后回到触发按钮。Esc只取消对话，不等同批准或丢弃草稿。
4. 多行输入Enter默认换行；发送使用明确按钮，Ctrl/Cmd+Enter作为可选快捷键并提示，防止中文输入法组合时误发送。
5. 状态更新使用适度aria-live；长AI回复不逐字打断读屏；错误就地显示并定位到对应字段。
6. 保存/审核请求中避免重复动作，但不靠禁用整个页面隐藏未知状态；恢复后焦点返回可执行下一步。

## 确认与错误文案

- 用“保存作品/提交审核/退回修改”，不用manifest、Provider、rowVersion作为员工按钮名称。
- 区分“未保存、保存失败、结果未确认”，不把网络超时全部写成“请再试一次”。
- 审核分“批准专业审核/批准发布审批”；显示“已批准，尚未发布”，避免把内部批准冒充外部结果。
- 附件明确“已上传/未用于本次生成/不能读取/权限不足”，不用模糊的“已理解”。
- 无权时显示可理解原因和返回动作，技术错误码放高级详情，不能暴露密钥、敏感正文或其他品牌资料。

## 中英文资源

COPY.zh-en.json提供关键文案key、中文及英文。P2使用显式key，不依赖扫描中文模板猜测翻译；英文可伸长，按钮和窄屏须人工检查。

受保护内容：员工输入、已保存正文、AI候选原文、资料引用原文、品牌名、文件名、URL和日志。语言切换只切换UI，不改变这些内容、不触发业务写入、不清空当前草稿。

静态画板目前为中文；提供配对文案不等于英文画面或运行期语言切换验收通过。英文版P2原型和实际键盘/读屏测试列入P2任务，不在P1冒充完成。
