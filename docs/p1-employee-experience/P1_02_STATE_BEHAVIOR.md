# P1-02 状态与恢复约束

日期：2026-11-02。完整状态ID见STATE_CATALOG.json（32项）。以下为前端显示/交互设计，不是数据库新枚举，也未修改真实接口。

## 状态驱动的主要动作

| 状态组 | 必须显示 | 主要动作/禁止行为 |
|---|---|---|
| T01/T02/T03/T04 | 任务下一步、最新反馈、期限或审核职责 | 一次进入正确上下文；不能对无权角色显示审核按钮 |
| T05/T06 | 无结果/无权/任务已变更分别说明 | 调整筛选或返回；不继续旧任务操作 |
| C01/C02 | 有任务/自由创作位置明确 | 自由讨论不自动创建任务；保存作品才确认任务 |
| C03/C04/C05 | 生成中、候选可选、替换未保存作品的影响 | 防重复发送，候选不自动覆盖作品，替换须明确确认 |
| C06 | 未接通、额度不足、失败区别 | 输入保留，可手动编辑；不展示假生成成功 |
| C07/C08 | 文件上传/授权/本次使用/可读性分别说明 | 不授权则不外发；未就绪文件不默认为作品已提交 |
| C09/C10/C11 | 未保存、保存中、当前已保存 | 保存后才能送审；保存响应必须匹配本地当前编辑 |
| C12/C13 | 保存失败/服务器更新 | 保留我的输入；不自动覆盖或用更新rowVersion强制重试 |
| C14 | 请求已发送但结果未确认 | 查询核对，不自动重复创建或送审 |
| C15 | 保存时又产生新编辑 | 显示仍未保存；旧快照保存成功也不能直接送审 |
| C16 | 可恢复输入与当前服务器作品区别 | 先预览再恢复，不能跨品牌/任务/版本无条件覆盖 |
| C17 | 送审对象摘要、确认、提交中 | 不重复提交；未知提交结果先核对服务器状态 |
| C18 | 切换上下文/资料撤权 | 隔离缓存、停止新外发，不将旧响应写入当前品牌 |
| R01/R02 | 专业/发布类型和对象只读 | 只显示服务端允许动作，保持同版本前置条件 |
| R03/R04 | 具体退回意见、修改入口、修订与复审关系 | 不修改旧冻结作品，不继承旧批准 |
| R05 | 已批准但未发布 | 交给发布负责人安排，不自动发布或入库 |
| R06/R07/R08 | 无权/自审/撤权、对象变化、未知结果/并发 | 阻断无效批准；刷新核对，不自动重复决定 |

## 保存、冲突与结果未知

P2应模拟三种不同结果，不能都归为“失败重试”：

1. 已知未保存：保留输入，恢复连接后可重试；只有服务端确认的版本可送审。
2. 409冲突：并排或分段展示“我的未保存输入”和“服务器当前作品”；允许保留草稿或在确认后基于当前版本重新编辑，不能静默覆盖。
3. 结果未知：写入可能已成功，查询当前任务/作品与操作结果，无法可靠关联时仍保持未确认，不自动重复创建。查询得到别人已处理的状态也不能声称“我的请求成功”。

现有多HTTP新建任务/作品不具备完整幂等结果协议。P1定义所需用户行为，P2显式Mock；P3必须设计关联、幂等与恢复方案后才能实现可靠“查询保存结果”，不能只做一个刷新按钮就声称问题解决。正式API如需新增能力另行评估，P1不改契约。

## 未保存内容与退出

- 设计必须区分内存保留、服务器草稿、已保存作品；不得承诺不存在的恢复能力。
- 同页切换讨论/作品不能丢输入；跨任务/品牌先提示，恢复对象带用户、品牌、任务和版本范围。
- 离开前可保存或保留草稿；若没有可靠草稿存储，明确“仅本页保留，刷新可能丢失”，不使用无条件恢复承诺。
- 恢复旧稿先预览，服务器已变化、作品冻结、身份变化或引用撤权时不能自动恢复后送审。

P3决定持久草稿机制；本设计不要求把敏感正文默认写到localStorage，也不把浏览器关闭事件当成可靠服务器保存。

## 权限、资料与上下文

品牌/任务/身份在请求发出时固定，读取响应过期则忽略；已经发出的写入不能因用户切换页面就断言未执行。发生撤权时停止新外发并隐藏被撤权资料的预览/下载，不能把相关资料自动复制到新品牌。本人未保存编辑的恢复也须遵守资料策略，不提供“导出所有资料”绕过路径。

模型读取声明只基于可验证能力和本次请求证据。无法确认是否使用资料时显示未确认；未知密级及不可信元数据沿用后端拒绝，不能让前端的文件chip放行。

## 审核和重复操作

审核的主体和快照不可编辑。确认框标明本次审核类型；退回必填意见；提交中禁用重复决定。撤权、自审、G3授权不足、专业审核未通过、版本摘要不一致或已被处理时均以服务端拒绝为准。

已有历史记录提供上下文，不把历史意见直接算到新作品上。作品级意见首批可用；未来段落/画面批注须有版本定位和失效规则，P1不擅自扩张。
