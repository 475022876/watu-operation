# 入口演练与回滚

基线：`95c24deaff853eb310deea0f99953fcb8d0a0f88`；P4 代码提交：`82f473b6a8ce343a2e264d9cf9fc7bf815ce2a66`。

本轮只演练隔离入口，没有执行生产部署或替换原 `/mos/`。`tools/p4/preview.cjs` 复制源码及已构建 public 资源到自身新建临时目录，使用独立 JSON、账号和网络保护；不复制业务库、config.json、素材或密钥。

## 已验证

- `node tools/p4/concurrency-test.cjs`：同一隔离服务的旧 HTML 与试点 HTML 都可访问，仅选入口不修改 JSON 文件；旧入口链接保留当前任务。此项包含在该套 14 个检查中。
- `node tools/p3/rollback-test.cjs`：保存作品后停服务，将隔离副本两个路由恢复至 c88a414，再重启；启动未改写 schema8 文件，已有账号和作品可读，2/2 通过。该对照比 P4 起点更早，证明没有引入新数据结构，不能证明可任意回滚生产状态。
- 实际 Chrome 取消回原入口时，仍保留当前未保存输入；恢复旧入口不会替用户删除已保存版本或审批。

## 撤除本轮预览

停止 `tools/p4/preview.cjs` 的专用进程即可撤除 9104 预览，正常退出会清理其临时目录。不要把该临时目录清理方式用于原数据目录。旧 9083、P2 9094、P3 9095 不需要停止或覆盖。

## 代码回滚

使用独立分支上的 `git revert` 撤销 P4 提交，或在干净的新工作树检出 P4 起点后重新构建试点。不要强制重置用户工作树、删除历史分支或将回滚当作业务记录撤销。构建产物被忽略，不自动入库；变更或撤除静态入口不等于撤销已经批准的内容。

## 正式切换条件

仍需员工试用记录、人工审查、受控目标环境、真实数据备份及恢复校验和明确部署授权，才可讨论正式替换入口。本轮没有形成双写、生产迁移或外部发布。讨论保留策略、文件扫描/孤儿清理以及未知请求的服务端关联 API 尚未新增；不能把当前人工核对策略宣称为自动恢复已经完成。
