# P4 前置条件与停止点

P3 本轮停在可审查的隔离文字 API 试点，不自动进入 P4。

下一步建议先完成：

1. 人工试用“任务 → 选定作品 → 保存 → 送审 → 退回 → 修订 → 分级批准”。至少作者、审核员各一人，记录理解错误与求助位置，确认版面与文案。
2. 审查 `legacy-ui-comparison.json` 的 12 项基线失败，区分旧断言与真实功能入口缺口，逐项修复及复验后再决定替换旧入口。
3. 决定创建/修订请求关联与未知结果核对是否需要新增内部 API。当前只采用既有接口加人工核对，不伪称自动幂等恢复已完成；新增契约另行评审。
4. 决定是否持久化讨论及其保留期限、敏感资料权限和清理策略；当前讨论不入任务/审批，不保证刷新恢复。
5. 正式文件安全扫描、上传结果关联、孤儿文件清理与 Workspace 实时授权保持独立要求；现有扩展名和魔数校验不等于完整安全扫描。
6. 真实模型需要独立批准 Provider、测试身份、脱敏资料与金额上限。当前试点限定 Mock，不读取生产凭据。
7. 确认代码提交后，另行授权 P4 的稳定、可访问性、旧入口兼容和正式切换演练。

图片/视频制作、Postiz、Activepieces、真实发布、正式资产入库改造及 PostgreSQL 业务切换仍不在本次范围。
