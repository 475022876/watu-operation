# 实现、影响与回滚

## 实现方式

- `navigation.ts` 定义六区和模块白名单。新任务制作/审核保留，其他页面直接挂载自己的既有 ES Modules，不加载旧 app.js、不嵌 iframe、不再显示第二个侧栏。
- `module-host.tsx` 提供同一品牌、身份、字典、参数、语言、导航和弹窗根；旧模块样式以 CSS `@scope` 限制在模块内，避免覆盖员工侧栏。仅在实际 Chrome 验证，其他浏览器仍需兼容性验收。
- 在同一父界面保留作品、图片/视频与任务关联；旧模块中的任务跳转进入新作品面，活动/选题的任务筛选进入完整任务表。带任务的模块链接会重新经服务端读取并验证品牌。
- API 客户端只增加可选的请求计数观察，不发出 URL、请求正文、Cookie 或密钥；原响应与错误语义不变。模块挂载、请求及弹窗操作未结束时阻止切换，卸载和下一次挂载串行，避免复用单例上下文串到另一品牌。
- 语言变化不重建编辑内容；权限撤销后移除管理入口。角色增加而当前页面仍可访问时保留未保存编辑，身份或品牌权限失效时安全阻断。
- 折叠冗长使用说明，隐藏重复旧标题，保持一个工作区标题；发布不会自动执行、OAuth 未接通等关键边界保持直接可见，没有为了简洁隐藏实际不可用状态。

## 确认并修复的实际衔接问题

| 问题 | 修改 | 证据 |
| --- | --- | --- |
| 当前品牌项目混入其他可见品牌 | `projects.js` 按当前 ctx.brand 过滤聚合结果 | 跨品牌展示浏览器检查 |
| 上传/图片素材关联在 projectRef.taskId，却未进入任务资料列表 | `task-workspace.js` 在同品牌约束内纳入现有 projectRef.taskId；不改响应字段 | 真实上传 → 任务资料 → 当前作品附件保存 |
| 视频相同任务选择重复读取；切任务期间旧表单仍可编辑、随后被响应覆盖 | `video.js` 同任务不重读，读取期间禁用旧表单，校验宿主/品牌/任务再采用结果；失败保留原内容 | 首次集成失败复现，修复后视频保存与未保存保护通过 |
| 图片/视频未带入当前任务 | 图像请求/上传传已有 taskId；视频从已验证任务参数选择；提供回任务按钮 | 图像及视频实际接口衔接检查 |

没有修改 Enterprise Workspace、正式双系统契约、Provider 安全策略、数据库架构或审批权限。唯一业务路由变更是现有任务资料查询补齐关联方式；其他主要是前端兼容与隔离工具。应用仍为 V0.1.6 / schema8 JSON，没有迁移或双写，没有新增依赖。

## 影响与限制

部分页面仍使用兼容模块的表格/表单，并非全部重新设计；真实员工仍需走查其理解成本。既有 JSON 单进程和未全面事务化的风险未被本轮消除。活动、素材等旧接口缺少服务端请求关联时，不应自动重放未知创建结果；本轮没有把兼容层称为新的事务或幂等服务。

## 回滚

旧 `/mos/` 和 P4 试点入口保留。停止本次 9106 专用预览可撤除新试用服务，不需停止其他服务。正常退出会清理其临时库，因此不要把正式资料放入该环境。

代码在独立分支上通过 `git revert` 撤销本轮提交，或新建干净工作树检出基线再构建；不要覆盖有用户修改的目录。撤换前端不撤销内容批准，不删除业务数据或历史审核。本轮没有生产部署，正式替换仍需另行人工验收和授权。

当前服务最后一次只更新生成的静态资源：数据库更新前后 SHA-256 一致、没有重启，见 `evidence/preview-refresh.json`。没有读取或合并原工作树与整改树的真实业务库。
