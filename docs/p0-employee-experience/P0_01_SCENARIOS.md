# P0-01 员工场景与工作脚本

日期：2026-11-02。事实来源：用户菜单图、操作体验反馈及现有源码。下列业务样例为**脱敏合成情境**，不代表已经开展员工访谈或取得真实品牌宣传事实。

## 角色边界

| 用户角色 | 工作目标 | 不应承担的操作 |
|---|---|---|
| 发起人/品牌运营负责人 | 说明交付要求、负责人、期限，跟进进度 | 创建模板版本、配置模型、理解资料技术ID |
| 制作员工 | 获取授权资料、创作、修改、选择交付作品 | 手动拼接聊天/素材/版本/审核对象，管理密钥 |
| 专业审核人 | 检查金融事实与业务合规，提出可执行意见 | 代替发布审批、默认批准自己的内容 |
| 发布审批人 | 批准明确的待发布作品及附件 | 批准未冻结的草稿、在作品变化后沿用旧批准 |
| 技术管理员 | 维护能力配置、预算和安全策略 | 自动取得独立最终入库审批权 |

角色按现有RBAC与品牌范围匹配，不依赖上述自然语言角色名直接授予权限。发起人可有审核角色，但仍不能自审；独立专业审核与发布审批仍按风险和政策分开。

## 三条主工作脚本

### S01 领到工作，知道从哪里开始

合成任务：“VFIB会员服务介绍短文”，要求使用已授权的服务资料，不编造收益、费率或资格条件；负责人为VFIB范围制作员工。

1. 员工进入“我的任务”，默认看到需要自己处理的工作。
2. 从名称、期限、进度和下一步判断优先级；不阅读代码或长说明。
3. 点击“开始/继续处理”，同时看到要求、已提供资料和当前作品。
4. 缺少资料时能明确识别缺口；不把空引用显示为“AI已读取”。

输入：任务要求、负责人、开始/截止、经授权文件。输出：进入正确品牌和任务的创作上下文。
主要动作：继续处理。次级动作：查看要求、联系发起人、管理员催办。
失败脚本：任务被撤权/取消、品牌变化、请求延迟；必须阻断或提示，不跳到其他任务。

### S02 讨论并选定一份作品

1. 从任务进入创作工作区，自动带入可用要求和授权资料引用，允许核对。
2. 员工输入内容目标，对话连续修改两次；模板/模型参数不占主屏。
3. 员工选中某个候选结果，在“当前作品”中整理；对话和交付稿清楚分开。
4. 点击保存到任务，明确反馈保存结果，不靠手工复制。
5. 作品和勾选附件准备好后提交审核；聊天记录不在审批对象中。

输入：任务上下文或自由创作需求、可用资料。输出：绑定同一任务的已保存作品。
主要动作：生成/继续修改→选为作品→保存/送审，动作随阶段变化，不同时展示全部按钮。
失败脚本：模型未配置、预算不足、无权外发、模型读取文件不支持、保存冲突/断网；保留输入，显示真实失败，不编造作品。

### S03 根据明确意见修改并完成交付

1. 独立审核人从待处理队列进入同一冻结作品，先看正文/附件和要求。
2. 审核人批准或退回；退回必须填写可操作意见。
3. 作者在“待修改”任务中看到该意见，继续编辑新修订稿。
4. 新稿保存并重新送审，旧版本及旧审核记录保留。
5. 当前稿按政策完成独立专业审核/发布审批后，显示可交付/可安排发布。

输入：冻结作品、审核授权、反馈。输出：批准的指定作品版本，而不是已对外发布。
失败脚本：自审、跨品牌、撤权、并发审核、作品/附件变化、旧批准重放；前端给可理解解释，服务端拒绝无效操作。

## 供P1/P2使用的五个走查任务

| 编号 | 参与者 | 观察目标 |
|---|---|---|
| U01 | 制作员工 | 找到今天的任务并进入正确上下文，列表到任务一次主要操作 |
| U02 | 制作员工 | 两轮修改后只保存最终正文，不保存整段聊天 |
| U03 | 制作员工 | 添加文件并送审，能准确说明本次交付了什么 |
| U04 | 独立审核人+作者 | 退回→读意见→修改→复审，无需另找文档或审核单编号 |
| U05 | 制作员工 | 保存失败后找到未保存内容，恢复时不误送审旧稿 |

另用UCARD合成任务进行品牌切换和隔离观察，禁止把VFIB资料带入UCARD。语言、窄屏和键盘操作是同一任务的变体，不另建业务对象。

## 仍需真实员工确认的假设

- 是否更常从“我的任务”进入，还是从自由创作进入；先默认任务入口，原型保留自由创作。
- 文件是否多数由发起人提供；先以任务资料为主，允许员工补充。
- 对“批准交付”与“发布成功”的理解；界面必须区分。
- “待修改”是否比项目进度更重要；先在个人队列突出，而不删除项目视图。

上述为设计假设，不因本文件完成而视为用户访谈通过。P1可以使用合成任务推进，不读取真实机密资料；用户确认前不把假设转为不可逆业务规则。
