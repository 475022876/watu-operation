# 真实双系统联调步骤（Consumer牵头）
1. **固定基线**：记录双方repo commit、应用版本、API规范SHA256、Staging URL（脱敏）、环境和启动命令。两套应用各自独立数据目录，绝不可指向真实生产资料库。
2. **启动Provider**：由资料库侧在隔离环境运行；确认接口可达与安全证书有效。Consumer只读其交付契约，校验hash。
3. **建测试身份**：Provider由授权管理员创建测试普通员工、P1、管理员、品牌隔离用户和显式授予特殊审批权的**测试身份**；正式真人授权只能由用户批准，在验收表中分开记“机制通过/人工待办”。
4. **签名与票据**：获取安全传递的测试凭据，执行正常和无效签名、nonce重放、过期、跨品牌、密级禁止测试；日志以requestId关联两端，不输出秘密。
5. **正式资产案例**：MOS创建Working Asset→表单填三必填字段→真实reviews审核→提交最终批准→Provider持久化→返回正式assetId/version→MOS可复用；重复同幂等键不得重复入库。失败后仅查询及原键恢复。
6. **Skill案例**：使用明确标识测试的合成Skill先检验链路；真实Skill V1.2只有人工审批/生效之后才能验证“权威生效”，否则BLOCKED。
7. **撤回案例**：Provider撤回已接入测试资产，Consumer轮询接收、失效本地引用，后续新调用被Provider拒绝；再做断线、事件截断/丢失、品牌事件隔离与游标持久化重启。
8. **归档隔离案例**：MOS发布已获批测试内容→生成发布快照/记录→Provider不产生Published镜像；从历史成品提取正式母版须重新走准入。
9. **完整生产路径**：情报源→Topic→Content Task→文本/视觉→三线审核（适用）→Publication→Archive→资产申请；AI外部未配置应分别记BLOCKED，不允许用mock宣称REAL_PASS。
10. **全量回归**：双方各跑本项目测试+浏览器流，执行恢复演练；生成逐INT证据+联合报告。

**失败必报：** 阻断接口、无法获得真人最终授权、缺正式文件、缺AI凭据、无浏览器或TLS环境。不能擅自补默认凭据或使用公开生产数据。
